# FA-WORLD-034 — Server-authoritative terrain validation

Status: implementation candidate; draft PR; no production deployment.

## Scope
- Recompute terrain on the Worker using the canonical 64×64 terrain generator constants.
- Validate the spawn tile during POST /world/:zoneId/join.
- Validate both source and destination tiles during POST /world/:zoneId/move.
- Permit water traversal only on the exact one-cell bridge links generated by web/src/world/bridges.ts.
- Preserve cardinal-only movement and compare-and-swap presence revisions.

## Canonical generation contract
The Worker mirrors web/src/world/terrain.ts:
- Sector: 64×64.
- Seed: 20261128 (current default terrain seed).
- Spawn safety: center (32,32), radius 4, forced grass.
- Fractal noise: scales 28 and 20; octave weights 0.55 / 0.30 / 0.15.
- Terrain classification thresholds: water < 0.31; rock > 0.76; snow > 0.68 with moisture < 0.48; forest moisture > 0.67; sand moisture < 0.27; otherwise grass.
- Bridge rule: a water tile is traversable only when it has walkable opposing east/west banks, otherwise walkable north/south banks.

## Validation
web/src/world/serverRulesParity.test.ts compares all 4096 server-generated cells against the canonical client map, compares every bridge cell, and checks movement rejection rules.

## API behavior
- Invalid spawn tile: HTTP 422 world_spawn_blocked.
- Non-cardinal move: HTTP 422 movement_must_be_cardinal_adjacent.
- Non-traversable source or destination: HTTP 422 movement_terrain_blocked.
- Existing revision conflict behavior remains HTTP 409.

## Security boundary — not production authentication
The current player identifier remains browser-generated and is not an authenticated identity. This lot prevents clients from walking through water/rock or inventing bridge links, but does not prevent identity spoofing, replay outside the revision contract, arbitrary player-state writes, or abusive request volume. Do not enable public competitive multiplayer until authenticated sessions, ownership checks, rate limiting, and server-side combat/economy validation are implemented.

## Deployment
No D1 migration is required for this lot. No Worker deployment is performed by this change.
